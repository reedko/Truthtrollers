# Codex Mandatory Compatibility Addendum: Preserve and Reproduce Existing Evidence Metrics

This addendum is binding on the locked CFX document-centric evidence plan.

## Governing correction

The existing production evidence metrics are not optional decoration and must not be silently dropped because CFX uses a cleaner semantic architecture.

The purpose of CFX is to improve:

```text
evidence discovery
evidence acquisition
evidence-assertion extraction
multi-assertion linking
target-relative bearing
```

while preserving the useful production outputs already earned through the legacy Evidence Engine.

The implementation is not complete if CFX produces links and stances but discards, nulls, or bypasses useful existing metrics without first reproducing their actual production semantics.

## Hard rule

Do not leave these fields null merely because the current CFX bearing schema does not yet emit them:

```text
score
support_level
confidence
source_quality_score
source_quality_tier
quality or bearing metrics shown in Workspace
```

Instead, trace exactly how the known-good production Evidence Engine generated, persisted, transformed, and displayed them.

Null is permitted only when:

1. the legacy metric genuinely was unavailable for that row;
2. the legacy producer also left it null under the same condition;
3. the metric cannot be computed honestly from available inputs;
4. the audit proves the metric was dead, misleading, or not consumed;
5. the implementation report explicitly identifies the reason.

“CFX does not currently emit it” is not an acceptable reason by itself.

## Required diligence audit

Use one or more known-good historical production tasks whose Workspace pages display:

- document-level links;
- assertion-level links;
- support/refute/nuance;
- numeric stance or support rating;
- confidence;
- source/evidence quality;
- rationale;
- quote or evidence text;
- scrape status;
- any aggregate counts or gauges affected by those metrics.

Trace each visible number end to end:

```text
legacy model or deterministic producer
→ intermediate object
→ persistence function
→ database column
→ API serializer
→ Workspace component
→ displayed value or aggregate
```

For every metric document:

- exact producer function;
- exact input fields;
- exact output range;
- formula or prompt definition;
- deterministic transformations;
- clamping, rounding, normalization, or defaults;
- database column and type;
- API payload field;
- frontend renderer;
- whether it affects totals, sorting, filtering, colors, or gauges;
- whether users can edit or verify it;
- rerun/update semantics;
- whether the metric is bearing, confidence, source quality, quote quality, relevance, or something else.

Do not merge unlike metrics simply because they all use numbers from 0 to 1 or 0 to 10.

## Required classification

Classify every existing metric as one of:

```text
preserve unchanged
reuse deterministic calculator
reuse model assessment with a narrow CFX prompt field
recompute from new CFX validated inputs
preserve as legacy compatibility projection
replace only after explicit product decision
retire because provably unused or invalid
unknown, implementation blocked
```

No metric may be dropped or retired merely because the new architecture does not currently have a matching field.

## CFX compatibility requirement

The new pipeline must produce the same useful Workspace-visible product contract as a known-good legacy run:

```text
evidence document
reference assertion
document-level claim link
assertion-level claim link
support/refute/nuance or compatible relation
numeric support/bearing rating
confidence
source/evidence quality where previously available
rationale
quote/exact excerpt
scrape/access state
manual and AI link compatibility
```

CFX may add stronger provenance and validation, but it must not regress the existing display or metrics.

## Separation of metric meanings

Preserve these as separate concepts:

```text
bearing relation
bearing strength / support level
model confidence
retrieval relevance
source quality
access quality
quote/excerpt validity
final evidentiary weight
```

Do not let the new document-centric bearing model invent source quality.

Do not let source quality change the extracted bearing relation.

Do not treat retrieval relevance as bearing strength.

Do not treat model confidence as truth probability.

Reuse the old definitions where they are sound and visible in production.

## Preferred implementation strategy

Where possible:

```text
new CFX validated bearing output
→ adapter into existing production metric calculator
→ existing persistence columns
→ existing API payload
→ existing Workspace rendering
```

If a metric was generated by a legacy model prompt, extract only the minimal scoring subtask or field needed and place it in a narrow CFX-compatible call or post-bearing scoring stage.

Do not revive the legacy Evidence Engine orchestration wholesale.

## Required tests

Add regression tests using known-good legacy fixtures or frozen artifacts proving:

1. CFX populates every metric that the legacy run populated for an equivalent accepted link;
2. the numeric ranges match production expectations;
3. deterministic transformations match legacy behavior;
4. support, refute, and nuance ratings preserve sign/direction conventions;
5. confidence remains distinct from support level;
6. source quality remains distinct from bearing;
7. null appears only in conditions where the legacy behavior or explicit metric contract allows it;
8. Workspace displays the same metric fields for CFX-generated rows;
9. aggregate totals and gauges do not regress;
10. user-verified values are never overwritten by reruns;
11. provenance records identify whether each metric came from:
    - legacy-compatible deterministic calculation;
    - CFX model output;
    - source-quality assessment;
    - user input;
    - historical preserved value.

## Implementation gate

Do not declare Workspace compatibility complete until:

- all existing visible metrics are traced;
- all sound metrics are preserved or reproduced;
- any null values are explicitly justified;
- UI payloads are regression-tested;
- known-good legacy and CFX-generated rows can be compared side by side;
- no useful metric has disappeared merely because of schema redesign.
